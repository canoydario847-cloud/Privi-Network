# Privi mainnet — Initial internal security review (2026-10-18)

**Review type:** Preliminary source/configuration and automated CI review performed during development. **NOT** an independent audit, external penetration test, third-party certification, formal security opinion, or approval to launch financial mainnet.

**Scope reviewed:** Privi Network branch \`launch/mainnet-readiness-gate-20261017\` (cap keeper, source patch, SDK mint tests, owner-operated topology, GitHub CI); pinned Cosmos EVM v0.7.3 mint-module source; developer cluster bootstrap. Evidence from [GitHub Actions #215](https://github.com/canoydario847-cloud/Privi-Network/actions/runs/39135131297) — **all five jobs PASSED**, including custom build and separate SDK bank+KV persistence tests. Source and test outcomes do not prove all host, chain or crypto risks are mitigated.

## Findings / prioritized remediation

| ID | Severity | Finding | Evidence | Remediation / status |
| --- | --- | --- | --- | --- |

| S-02 | **HIGH** | Immutable cap record and block-boundary supply check do **not** prove no lifetime remint after burns: net circulating PRVI can remain below initial genesis amount after unauthorized burn-then-mint. | \`prvicap.Reconcile\` compares current bank supply with genesis, not all historical mutations. | **OPEN:** audit all mint and burn paths, instrument native issuance accounting at every consensus bank mutation; full-chain adversarial tests of burn/mint, upgrades and imports. |
| S-03 | **HIGH** | Final customized PRVI genesis/InitChain and full EndBlocker/BeginBlocker runtime have not been exercised as a real Privi multi-module chain. | CI custom app build compiles the patched \`evmd\`; the four-validator smoke job runs **unmodified upstream** with valueless \`atest\`. | **OPEN:** run exact customized binary with reviewed valueless genesis; verify failures, chain restart, upgrade, state sync, EVM/IBC routes. |

## Automated controls added (candidate only)

- [owner_validator_preflight.py](owner_validator_preflight.py) ensures exactly 4 validator records, one owner, unique host and fault domains, unique node ID/signing fingerprints, RFC1918/ULA-style private peer IPs, loopback RPC and metrics, approved signer categories and no private key/secret fields. **It neither generates nor accesses validator signing keys.**
- [test_owner_validator_preflight.py](test_owner_validator_preflight.py) challenges duplicate identity/fault domains, public/unspecified addresses, secret fields, unsafe signers, multiple operators, wrong vote power, and premature financial enablement.
- A draft inventory must retain financial issuance and launch **OFF**, and the CLI's \`--mode preflight\` refuses self-certification even with apparent complete form fields. A human-audited signed artifact chain remains necessary.

## What was NOT audited

Live validator hosts (none provided), actual contract state, private keys, independent penetration tests, on-chain production runtime, governance/key signing infrastructure, node attestation, final genesis, actual four-host network, token sale compliance, and specific counsel approvals. No public claim of "government-grade", "fully audited", "decentralized" or "production secure" is supported.

**Verdict: FINANCIAL PRVI MAINNET NO-GO.** The review identifies concrete security risks and adds negative tests, but it is **not a substitute for independent auditors or real infrastructure**. TEST/atest remains permanently valueless; BNB Chain PRIV remains separate.
